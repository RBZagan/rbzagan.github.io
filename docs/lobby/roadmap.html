Roadmap

The order things are being built in, and roughly why each one is sequenced where it is.

Stages

  1. 1
    Project scaffold

    A Rojo project that maps the four source directories onto Roblox services, plus the strict-mode typing configuration. Until this lands there is no tree to build inside.

  2. 2
    First module and entry point

    One real module, wired as the package's public entry point. It exists to prove the structure end to end — sync, type-check, require — before the package grows.

  3. 3
    Session entry

    Player join and leave, the authoritative session state that backs it, and the remotes a game mode calls to drive a transition.

  4. 4
    Presentation layer

    The shared lobby UI — navigation between game modes, and the client-side prediction that makes a transition feel immediate while the server confirms it.

Not planned

These are deliberately out of scope rather than deferred, so nobody builds something the package was never going to accept:

  • Game-mode logic. The lobby fronts the modes; it does not contain them.
  • Matchmaking. Selection happens against a service the package treats as opaque.
  • A client-authoritative data path. See how it works.
