Getting started

The stack the package runs on, and what depending on it looks like from a game mode's side of the boundary.

The stack

Tool Role
Rojo Maps the source tree onto the live tree, so the package is committed as files rather than as a place file.
Roblox Studio Hosts the live tree the source tree syncs into.
Luau The implementation language, in strict mode throughout.
Lua Language Server Type checking, configured per repository and committed alongside the code it governs.

Editing it

Edit files on disk. The instance tree in Studio is a mirror of the source tree, and a change made only in Studio is lost at the next sync. The reverse is also true of deletion — removing a file removes the instance on the next sync, so the tree never drifts from the source.

Consuming it

A game mode depends on the package rather than vendoring it. Everything a consumer needs is reachable from the package's single public entry point; reaching past it is a sign the boundary is in the wrong place, not that the consumer is being demanding.

ⓘ

The package is still in development and is not published to the Creator Store. There is no version to depend on yet — see the roadmap for what comes first.

Requirements

  • A place running the Minigame universe, or a place that is adopting it.
  • Rojo and Roblox Studio for local development.
  • No other runtime dependency.
